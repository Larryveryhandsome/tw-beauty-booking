# tw-beauty-booking｜美業預約與會員關係系統（示範）

給美髮、美甲、美睫、美容工作室看的「可以自己按」的示範。純前端、免安裝、免帳號、免伺服器；所有店家、設計師、客人、電話都是**虛構假資料**，所有「發送 LINE」只在頁面內模擬，**不會真的發出訊息**。

> 線上試用：公開並開啟 GitHub Pages 後為 `https://larryveryhandsome.github.io/tw-beauty-booking/`

---

## 解決什麼問題

| | 傳統做法的痛點 | 用系統的做法 |
|---|---|---|
| 預約 | 客人 LINE 問「明天下午有空嗎」，老闆一邊做一邊回，來回好幾輪，還可能排到重疊的時段 | 客人自己選項目、設計師、時段。系統依「設計師 × 時間 × 服務時長」排，染髮 150 分鐘就占 150 分鐘，只顯示真的空的時段 |
| 爽約與遲到 | 客人忘記或臨時不來，空出一整段才發現；提醒得一個個傳 | 前一天、當天自動提醒，客人一鍵「確認出席」或「改期」 |
| 請假改約 | 設計師臨時請假，老闆翻本子、一個個打電話問客人改哪天 | 設計師按請假，系統列出受影響的客人，通知並附上可選新時段，客人自己點選就改好 |
| 回訪 | 客人做完就沒回來，過很久才想到「她是不是該補染了」 | 依項目週期提醒回訪（補染約 6 週、補睫約 3 週、凝膠甲約 3～4 週），週期可自己設定 |
| 儲值與套票 | 靠紙本或 Excel，客人問「還剩幾次」要翻半天 | 結帳時依套票、儲值金自動扣次、扣額，客人在 LINE 自己查餘額 |
| 月結 | 月底手動加總每位設計師業績、逐筆算抽成 | 依服務項目與「客人是否指定」自動算業績與抽成，比例在設定檔改，一頁看完 |
| 空檔（選配） | 平日下午空了一兩小時，只能在 IG 貼「今天有空檔」 | 找出連續空檔，挑適合的熟客推限時優惠，發送前由老闆確認名單 |

以上為功能說明，實際效果原則上會因店家的客群與使用習慣而不同，不代表任何保證。

三種角色各看各的畫面：**客人**（手機 LINE：預約、我的預約、餘額、訊息）、**設計師**（今日班表、請假）、**老闆／櫃台**（預約總表、回訪、儲值套票、月結抽成、空檔推播、LINE 紀錄）。

## 檔案

```
index.html          說明頁（痛點對照、角色、3 分鐘看完的順序）
demo/index.html     可操作的示範
demo/config.js      ★ 換成你自己店的資料，只要改這個檔案
tests/smoke.spec.js 冒煙測試（Playwright）
```

## 怎麼用

1. 下載這個專案（綠色 **Code** 按鈕 → **Download ZIP**），解壓縮。
2. 雙擊 **`index.html`** 看說明，或直接雙擊 **`demo/index.html`** 開示範；也可以用任何靜態伺服器開（例如 `npx serve`、`python -m http.server`）。Chrome、Edge、Safari、Firefox 都可以。
3. 在示範頁按 **「▶ 一鍵示範：設計師請假」**，約 40 秒自動跑完：設計師請假 → 找出受影響的客人 → 通知 → 客人自己挑新時段 → 總表更新。
4. 也可以自己玩：右上角切換「客人／設計師／老闆」，先當客人預約一次，再到老闆畫面看總表、回訪、儲值、月結。「重置」回到初始狀態。

網址後面可以直接帶畫面：`demo/index.html#auto`（自動播放示範）、`#book`、`#leave`、`#grid`、`#recall`、`#stored`、`#payroll`、`#gap`、`#log`。

## 換成自己店的資料（`demo/config.js`）

用記事本或任何編輯器打開 `demo/config.js`，改完存檔、重新整理網頁即可。每一段都有中文註解：

| 要改什麼 | 在哪裡 | 說明 |
|---|---|---|
| 店名 | `shopName` | 顯示在畫面標題與 LINE 圖卡上 |
| 服務項目、時長、價格 | `services` | 每項：`name` 名稱、`cat` 類別、`dur` 時長（分鐘，建議是 `step` 的倍數）、`price` 價格 |
| 服務類別 | `categories` | 美髮／美甲／美睫／美容，可自行改名 |
| 設計師 | `designers` | `name` 藝名、`title` 頭銜、`cats` 會做哪些類別、`off` 固定休假日（0＝週一…6＝週日） |
| 營業時間 | `hours` | 依序週一到週日，格式 `'10:00-20:00'`，公休寫 `'休'` |
| 排程格子 | `step` | 預設 30 分鐘 |
| 抽成 | `commission` | 各類別比例，以及客人「指定設計師」時再加的 `requestBonus` |
| 回訪週期 | 每個服務的 `cycle`（天）、`recallLead` | 週期到之前幾天開始列入回訪清單；老闆畫面「回訪」分頁也能直接改 |
| 儲值方案 | `topups` | 儲值金額與贈送金額 |
| 套票 | `packs` | 名稱、適用項目、次數、售價 |
| 示範客人與餘額 | `customers` | 儲值金、套票剩餘次數、各項目「距離上次幾天」 |
| 示範預約 | `bookings` | 一行一筆：`星期|設計師|開始|項目|客人|是否指定|狀態` |
| 本月累計業績 | `history`、`historyLabel` | 月結畫面用 |
| 空檔優惠 | `gapDiscount` | `0.9` ＝ 9 折 |
| 一鍵示範 | `demo` | 誰請假、哪一天 |
| 示範的「今天」 | `weekStart`、`todayIdx`、`nowMin` | 見下方已知限制 |

**說明頁 `index.html`** 是作者介紹這套系統的頁面（含聯絡方式），文字直接寫在 HTML 裡，要改就直接改 HTML。

## 給開發者

```bash
npm ci
npx playwright install chromium
npm test
```

冒煙測試（8 項）會用 Chromium 以 `file://` 直接開頁面，檢查：

- 說明頁與示範頁載入沒有 JS 錯誤
- 一鍵示範完整跑完，請假的設計師（Ken）當天變成 0 筆預約
- 客人預約後，同一時段（含時長重疊的格子）不會再出現
- 連續預約多筆（含 150 分鐘染髮），所有預約之間沒有重疊
- 備註欄輸入 HTML 不會被執行
- 手機 375px 時，客人、設計師、老闆各分頁都沒有橫向捲動

每次 push 由 GitHub Actions（`.github/workflows/test.yml`）自動跑。

## 已知限制

- **純前端、不存資料**：重新整理就回到初始狀態，沒有後端、沒有資料庫。
- **LINE 只在頁面內模擬**：所有通知、提醒、推播都不會真的發出。
- **示範的「今天」日期固定**：由 `config.js` 的 `weekStart`／`todayIdx`／`nowMin` 決定（預設 2026/11/25 星期三 12:00），不會隨真實日期改變；過了那一週，畫面上的日期仍是示範日期。
- 「受影響人數」「業績」「抽成」等數字是示範資料的計算結果，不代表實際營收。
- `config.js` 視為店家自己填的可信資料，不要把不信任的外部內容直接貼進去。
- 自動化測試只跑 Chromium；Firefox、Safari 與實體手機請自行確認。
